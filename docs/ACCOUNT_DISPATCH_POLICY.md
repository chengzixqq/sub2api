# 用户专属调度账号

管理员可针对“用户 + API Key 请求分组”设置账号策略。账号本身的可调度状态、模型支持、额度、限流和分组访问授权仍然生效；专属策略不赋予用户新的分组访问权。

## 策略

- **默认**：使用原有分组调度，但不使用标为“仅授权调度”的账号。
- **追加**：在原有普通候选上增加显式选择的账号。组外账号只对该用户在这个请求分组下生效，不改变它在原分组的行为。
- **指定名单**：只使用显式选择的账号。组内选择为空而组外追加非空时仍可用；整个名单为空或全部不可用时请求失败。分组新加入的账号不会自动进入名单。
- **恢复默认**：删除该用户的策略，不能用空指定名单代替。

账号可标记为“仅授权调度”，包括属于某分组或不属于任何分组的账号。它不会进入普通用户请求的默认候选，只有被显式选择时才有机会参与调度。首版组外授权只支持与目标单平台分组同平台的账号；默认工作区可直接使用，其他工作区必须处于启用状态，并持有该分组的有效授权。不支持复合分组跨组授权。已有上游请求和已提交的异步任务可完成；撤权阻止后续选号。

## 上线顺序

1. 应用新迁移，部署全部支持专属账号准入与新版调度缓存元数据的实例。此时保持 `SUB2API_ACCOUNT_DISPATCH_WRITES_ENABLED` 未设置或为 `0`。
2. 确认没有旧版网关实例，并使旧版调度快照失效或等待新版快照生效。
3. 在所有管理实例设置 `SUB2API_ACCOUNT_DISPATCH_WRITES_ENABLED=1`，重启后再创建“仅授权调度”账号或保存用户策略。

**不能在仍有旧版网关实例时打开写入闸门。**旧实例不识别账号隔离标记，可能将测试账号当作普通账号使用。发生问题时，先关闭写入闸门，再保留新版网关的读取和隔离逻辑；已有隔离账号或专属策略期间，不要直接回退到不识别它们的旧版网关。
