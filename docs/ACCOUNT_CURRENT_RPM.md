# 账号在用 RPM

`current_rpm` 表示上游账号在最近滚动 60 秒内成功完成的在线转发请求数，
不依赖账号平台、认证方式或是否配置 `base_rpm`。窗口为 Redis 服务端时间的
`(now - 60s, now]`，请求满 60 秒后移出计数，整分钟不会归零。
它不是 RPM 限额，也不补算升级前的请求；新版本接管流量后需要 60 秒形成完整窗口。

`scheduling_rpm` 单独保留原自然分钟累计，供容量和限流状态使用。
调度器、用户/分组限流与消息队列仍使用原计数器，不受展示窗口影响。

## 计数与读取

- 在线 Messages、Responses、Chat Completions、Embeddings、Alpha Search、Gemini、
  SystemOne、Grok 搜索/音频/媒体以及 Images 使用同一账号计数器。
- 一次请求失败后重试，只有成功完成的转发计一次；计费重试和异步结算不重复计数。
- OpenAI WebSocket 每个收到 `response.completed` 或 `response.done` 的成功回合计一次；
  连接建立、缺少完成事件、失败和 incomplete 回合不计数。
- Live 成功创建上游会话计一次，sideband 重连不另计；Grok Realtime 正常结束且观察到音频的会话计一次。
- 独立异步 Batch Image 任务的提交、轮询和下载不属于此在线转发指标。
- 计数写入最多等待一秒，保留请求取消语义；Redis 故障只记日志，不将成功转发改成失败。
  因而该值是运行观测指标，不应用作精确计费凭据。
- 列表 full/lite 对当前页账号做一次批量读取，详情读取当前账号；不产生逐行网络请求。
- 最近 60 秒没有成功请求时返回 `0`。缓存不可用或单个计数损坏时省略该账号的 `current_rpm`，
  批量读取仍保留其他账号的有效结果。已有 Anthropic 调度限额规则保持原有行为。

## 客户端

Web 账号管理默认在“容量”后显示独立的“RPM（近60秒）”列，可使用列设置隐藏或调整顺序。
数值随列表刷新更新，支持仅 RPM 改变时刷新；缺失显示“不可用”，不使用限额替代。
列表 ETag 包含运行时字段，因此计数变化不会被旧缓存遮蔽。

管理员首页、用户首页和 API Key 用量页使用同一成功转发事件流的全站、用户、Key 计数。
管理员的受限账号视图仅汇总授权账号。各页面分别读取，读数时间不同可能有少量差异。
首页的历史摘要和图表继续缓存，但每次响应重新读取 RPM，并更新最终响应 ETag。
`rpm_available=false` 表示实时计数不可用，不使用旧五分钟平均值作为替代。
TPM 与历史图表时间桶平均值维持原口径。

现有 Sub2 Mobile 已读取列表和详情中的可选 `current_rpm`，不需要更改认证或请求协议。
更新后端后，该现有字段即返回滚动窗口；旧后端缺失字段仍按“不可用”处理。

## 验证与回滚

回归覆盖 API Key/OAuth、未配置限额、full/lite/详情、跨分钟保留与精确过期、并发同刻事件、
Redis 局部失败、账号/用户/Key 隔离、缓存与 ETag、成功重试、终端失败、WebSocket 回合，
以及 Web 数值与列配置刷新。
变更不涉及数据库迁移；回退源码并重建服务即可恢复旧逻辑，短期 Redis 计数自动过期。
