# Sub2API 魔改版 v0.2.23 升级说明

此次同步从魔改提交 `162789896` 出发，合入官方稳定标签 `v0.2.23`（`5af9afb58`）。官方标签内 `backend/cmd/server/VERSION` 仍为 `0.2.22`，本版已修正源码构建的版本回显。

| 冲突 | 本版采用的行为 |
| --- | --- |
| Anthropic 缓存计费 | 以官方写入总量为准。总量 100、5m 为 20、1h 为 30 时，按 70 个 5m、30 个 1h 计费。保留 Advisor 分项及 OpenAI 的 30m/12h 计量。 |
| Responses 转 Messages | 优先采用有计量依据的 `response.usage`，其次是同帧顶层 `usage`。空对象不清除已观测的真实用量；明确给出的零仍有效。只在总量匹配时继承可核实的时长或图像明细。 |
| 缓存图像输入 | 仅在 Responses 转 Messages 时新增拆分。普通 Responses、WebSocket 和图片直连接口沿用各自原有的扣费方式。 |
| Ultra Fast 倍率和资格 | 非空 `ultrafast_multiplier` 只允许配置在渠道价卡。分组仍按整张价卡优先；采用官方 GPT-6.2 套餐和显式模型发现规则，账号调度授权不变。 |
| 重复的 Anthropic 终止帧 | 第一个完整 `message_stop` 结束响应，保留此前用量，不转发后续重复帧。 |

**计费示例。** 上游报告输入 1,000、缓存读取 600、图像输入 500，其中缓存图像 400。以每百万 token 文本输入 $10、图像输入 $30、缓存读取 $1、缓存图像读取 $3 为例：普通 Responses 仍为 **$0.012600**，Responses 转 Messages 为 **$0.007400**。Messages 若已观测到输入 200、输出 3，终止帧只报图像输出 4，不会清空原总量或将这 4 个另行计费。

**存量分组价卡。** 旧数据库记录或鉴权缓存快照里的 `ultrafast_multiplier` 在读取时忽略，其余分组价格保留。复制分组不会带上旧倍率；更新该分组并写回价卡时会去掉它。这次升级不会批量改写分组，提交非空分组倍率仍会被拒绝。

**旧库迁移。** 新增的 `252_channel_pricing_ultrafast_multiplier.sql` 与官方原文件一致，为渠道价卡增加可空正数倍率。已有魔改库如果已执行 `252_admin_access_tokens.sql` 及后续迁移，在预检里仅将新的官方 252 列为 `Pending` / `OutOfOrderPending`。历史已到 263 却缺少两条 252，或已执行文件的 checksum 不符，预检仍然失败。

现有 `deploy/upgrade-compose.sh` 要求 **零条待执行迁移**；即使新的 252 可以安全补跑，该脚本仍会停在更换服务之前。请先在测试库演练并安排备份和迁移窗口，确认待执行数为零后再走这一部署流程。不要改旧 SQL、checksum 或预检门禁来跳过迁移。

**账单与统计。** 两个父版本都让自定义账号统计价卡在全部输出的文本价上叠加图像价，客户账单则先拆分图文。此次保留该口径：统计金额可能与客户扣款不同，不会重复扣减客户余额。
