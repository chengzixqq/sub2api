# V2 渠道监控参数说明

本次配置扩展基于魔改 v0.2.15，保留已验收的卡片与交互动效。配置分为站点监控策略、探针目标、旧聚合兼容、全站显示默认值和本浏览器个人偏好。以下为源码默认值，不代表线上当前值。此次追加修复仅本地实现和验收，未保存生产配置、执行收费探测或部署。

## 站点监控策略

管理入口：渠道监控 → 监控设置 → 监控与阈值。使用 observation-config GET/PUT，站点所有者权限、版本冲突保护、保存后清概览缓存；原有 JSONB 配置继续使用，无新增数据表或迁移。

| 参数 | 默认 | 可设范围及作用 |
|---|---:|---|
| 真实请求采集 | 开 | 控制真实请求采集，也是探针运行的前置开关；不会自动打开付费探活 |
| 主动付费探活 | 关 | 需真实采集、付费探活、目标三个开关均开启；手动探测同样约束 |
| 额度监控 | 开 | 独立只读额度同步 |
| 发布模式 | shadow | shadow 使用旧聚合展示；live 对发布分组使用 compact 数据 |
| 发布分组 | 空 | 空表示全部分组，最多1000个；未发布分组继续旧聚合 |
| 页面刷新周期 | 60秒 | 30–300秒整数；通过概览响应传给管理端/用户端轮询，不改变聚合粒度 |
| 最少真实请求样本 | 50 | 1–1,000,000；不足时标记样本不足，不猜测健康 |
| 正常/警告可靠率 | 99% / 95% | 0 < 警告 < 正常 ≤ 100% |
| 首字延迟警告/严重 | 3000 / 10000ms | 0 < 警告 < 严重 ≤ 86,400,000ms，整数 |
| 流量证据有效期 | 300秒 | 60–3600秒；过期后可采用有效探针证据 |
| 探测连续失败阈值 | 2次 | 1–10；真实流量与探针证据仍分开显示 |
| 额度证据过期 | 600秒 | 300–3600秒；超过时效标记陈旧 |
| 探测间隔 | 900秒 | 60–3600秒；无近期流量且达到间隔时才自动探测，不承诺每个间隔必执行 |
| 探测超时 | 20秒 | 5–60秒；执行上下文、HTTP调用和数据库占用时限配套使用 |
| 单目标每日次数上限 | 96 | 1–1440；自动与手动探测共用预算 |
| 全站每日次数上限 | 1000 | 1–100000；UTC日重置，与目标预算同时约束 |

减少预算后已产生的调用不撤回；后续预约被限额拦截。预算按数据库事务原子预约，重复幂等请求不重复计数。间隔不是实时保证：调度每分钟检查，保留并发4、每轮最多8个的保护。

### 首字延迟覆盖规则

最多100条，平台/分组/模型精确匹配，空字段表示不限，至少填写一个。重复的选择器拒绝保存。优先级为：

平台+分组+模型 > 分组+模型 > 平台+模型 > 平台+分组 > 模型 > 分组 > 平台 > 全局阈值。

模型级规则影响模型明细；只有平台/分组规则可直接匹配不带模型名的渠道聚合，不将一个模型的阈值套给其他模型。

### 保持固定的运行边界

- 明细保留24小时；涉及去重、重放、分区清理与查询边界，不能只修改一个保存值。分钟聚合48小时、小时聚合30天按既有机制保留，不因显示设置删除历史。
- 额度只读同步使用既有5分钟最小间隔，避免扩大供应商API调用。
- 真实数据聚合粒度与查询范围配套；不把刷新间隔当作时间桶宽度。
- 探针输出采用既有最小文本策略，不开放任意付费提示词、敏感凭据或取消预算保护。
- 系统设置中的渠道监控入口总开关、V1/V2模式及数据可见性仍按既有权限生效。

## 探针目标

支持分组、精确模型名、协议（OpenAI Chat / Responses、Anthropic、Gemini）、启用开关。新目标默认关闭。模型、分组权限和支持协议由后端再次验证。目标保存冲突保留草稿，先重新加载最新版本再人工合并，不静默覆盖他人更新。

账号探针的上游地址遵循网关 URL 策略：仅在允许非加密 HTTP 时接受公网 HTTP；启用上游白名单时仍按网关规则校验。保留私网/回环/元数据地址拦截、拨号时 DNS/IP 复查及禁止重定向。地址被拒绝时返回 `endpoint_rejected`，不会向上游发出请求。

## 旧聚合兼容

这不是V1配置。原 V2 被动日志聚合保留启用开关、60/300秒聚合刷新、平台/模型/分组选择、计入健康判定的错误分类，以及旧评分样本、错误率、首字延迟、缓存命中率和三项权重。

权重为非负百分比且合计100%；缓存阈值0/0合法，表示不设缓存降级门槛。统一卡片包括 legacy 来源行都重新使用“监控与阈值”的可靠率和延迟规则；旧评分字段用于原 V2 输出。shadow 模式和 live 未发布分组仍受旧聚合数据选择影响。

## 显示偏好

紧凑/宽松密度、宽屏最大2/3/4列或自动、跟随系统/关闭动画、P95详情、默认模型展开、默认视图、默认时间范围、自动刷新开关。小屏自动减少列数。系统减少动态效果优先。矩阵初始按时间展示，维度和趋势分组使用原生选择器；视图标签支持方向键、Home/End 和减少动态效果设置。

站点所有者在 `/admin/channels/monitor` 保存“全站显示默认值”，作为所有用户未自定义字段的默认值。个人覆盖按账号、角色、工作区在本浏览器保存；“恢复管理员默认值”删除个人覆盖。历史完整偏好迁移时，仍等于旧内置默认值的字段视为未自定义。非站点所有者不能保存全站配置。

全站值保存在监控策略 `presentation_defaults` 中，与采集策略共用版本冲突检查。概览及 `presentation_only=true` 元数据返回 `presentation_defaults_version`；客户端拒绝较旧版本，避免晚到响应覆盖刚保存的设置。后台默认值更新保留尚未提交的历史草稿，显式恢复或切换身份会重新载入。

### 历史状态条：样本区间与数量

入口：显示偏好 → 历史状态条。这里的“分钟区间”指**每根状态条汇总多长时段内的请求样本**，不是每隔多少分钟取一个样本，也不是页面刷新或付费探测频率。状态颜色仍由该时段的真实聚合指标与健康策略决定，不保证每根都是绿色。

- **自动**：不发送新增参数，保留原默认；90分钟/24小时范围使用5分钟区间，7天/30天使用60分钟区间。
- **按分钟区间**：填写期望分钟数，正整数1–43200。近90分钟/24小时可用1分钟粒度；7天/30天只能使用整小时粒度。切换范围后向上对齐可用粒度、限制在所选范围内，保留原始浏览器偏好，并显示实际请求与返回的区间。
- **按目标条数**：1–720，服务端根据时间范围计算每格时长并向上对齐可用精度。目标条数不是硬裁剪数量；时间窗首尾可能含部分区间，所以实际条数可能多一根，或因数据粒度限制少于目标。

例如完整24小时：30分钟/条约48条，60分钟/条约24条，目标60条按24分钟/条汇总。卡片同时显示实际区间和实际条数；悬浮提示显示真实样本时段。输入修改后点击“应用历史设置”，非法值不会更新已保存偏好或触发新查询。

浏览器保存 `historyMode`、`historyBucketMinutes`、`historyBarCount`，管理端和用户端以互斥的 `bucket_minutes` / `bucket_count` 查询参数请求 `/overview`。后端真实汇总请求计数、错误与延迟直方图，不复制状态条、不只抽取部分历史，也不平均各桶P95。旧聚合数据源与compact数据源均接入；刷新、实时健康状态、采集配置与数据保留周期不随之改变，无新增表或迁移。

近48小时之外的compact历史只有小时级源数据，不能伪造分钟精度。边缘缺少完整源样本时保留部分覆盖标识，并通过可选 `sample_start` / `sample_end` 说明真正纳入统计的边缘样本窗口；它们不是有流量的第一条和最后一条请求时间。缓存按实际粒度与源粒度隔离。

“部分覆盖”也可能来自结果尚未归类的请求，与采集心跳正常并不矛盾；此时显示 `unknown_outcome` 对应的中文原因。历史采集队列丢失等真实缺口继续保留，不把未知结果改算成成功或渠道错误。

本地预览与真实用户页共用时间选择控件，支持90分钟、24小时、7天、30天；管理预览也可切换。预览按所选范围独立生成虚构样本，自动模式采用5/60分钟区间；显式区间或目标条数与所选范围联动，整样本计数守恒、覆盖缺口仍保留，用户模式仍隐藏运维计数。切换范围会关闭旧区间详情，账号角色的默认范围独立保存。预览不请求生产API；这些示例不是生产历史数据，实际数据库聚合的验证边界以本轮验证记录为准。

## 修复与验收

修复百分比0被默认值替换、空值与非法权重被静默纠正、未知错误分类静默丢弃、保存失败/版本冲突丢草稿、刷新保存后页面仍固定60秒、默认视图与过时layout偏好脱节，以及探针历史窗口不足以判定默认两次失败的问题。历史JSON缺少新增字段时补默认值；旧客户端保存未提供的新增字段保留当前值，显式非法值拒绝。旧聚合设置300秒刷新时，采集陈旧判定也随周期调整，避免正常数据被每2分钟误报陈旧。

本地验收入口：`http://127.0.0.1:3015/monitor-preview.html`。显示偏好直接改变示例卡片；“配置参数验收”复用真实表单与校验，保存仅在内存保留、跨页签保留，重载页面重置。付费探测在预览禁止执行；示例健康数据不根据试填阈值重新计算。实际运行语义由前后端回归验证。
